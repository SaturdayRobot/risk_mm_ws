# Agent 任务入口

本文件说明用户目标与验收方向；自动加载的仓库约定位于 [AGENTS.md](../AGENTS.md)。用户最新明确指令优先。文档中的计划和目标值不能作为已经实现的证据。

## 最终目标

在本仓库独立构建的 **Rangermini＋xArm6** 上，实现可在 Gazebo 和 C++ GUI 实际操作的自主巡检：从实测起点出发，依次通过多个有实际转弯与车臂联动要求的巡检点，最后回到起点。机器人运行当前轨迹时规划并验证后续轨迹，正常巡检不因等待规划停车，段间位置、速度和加速度连续。

规划应达到用户要求的毫秒量级响应；用户最新明确几百毫秒可接受，不要求几毫秒或几十毫秒。首轮按成功任务完整规划与验证响应低于 1 秒推进，并同时报告成功率、最慢耗时及相同硬件、地图、模型和任务条件下的原 REMANI 对照。该响应目标不是已验证成果，也不能用优化预算、失败候选耗时或缩减验证来替代。当前先完成规划与执行闭环，采图后续再做。

机械臂必须在 COUPLED 内显著参与主动避障：底盘行进过程中六关节按环境需要收肘、抬臂、侧转并恢复任务姿态。后续需优化当前近紧凑目标、逐点固定六关节与关节零速边界带来的保守性，用确实需要变姿的障碍任务证明协同收益，同时保持关节、四轮与碰撞硬限制。当前轮次先完成数值与模型适配修复；这项后续要求必须保留并验收。

新增核心逻辑使用 C++，保持接口清楚、实现简洁，复用已有规划、验证与执行模块；不通过添加多套候选算法、模式回退、重复包结构或过多防御性代码掩盖问题。

## 当前优先级

1. 完成 **COUPLED 连续巡检闭环**，同时保留已验证的单目标、方向、相机和速度配置。
2. 用可复现失败输入解决转弯几何、四轮可行性与连续时间映射问题，再验证不停步切段与返航。
3. 对成功任务统计耗时、成功率和执行效果，优化瓶颈；最后部署可见 GUI 验收并清理代码。
4. ARM_FIRST 是保留的第二模式，完整在线链尚待接通；不以此替代当前 COUPLED 目标。只允许 robot.yaml 的唯一 stow，不恢复 BASE_FIRST、姿态库或隐式回退。

具体当前方案、已完成内容、失败原因和下一个动作统一记录在 [当前进度与方案](current_work_progress.md)，不要在本文件另维护一份动态待办。

## 已确定的工程边界

- 只使用本工作空间的模型与资源；系统 ROS 2 Humble 加当前 install，通过 `scripts/in_env` 进入环境。
- REMANI 锁定原文保存在 `third_party/remani_original`，不可改写；移植变化、模型扩展和参数差异必须可追溯，见 [来源说明](../docs/provenance.md)。用户已有研究成果不被称为 REMANI 复现。
- 用户确认雷达侧为车头，即 `+base_control X`；`base_control` 相对保留的 `base_link` 绕 Z 转 pi。不要再翻转相机或修改出生朝向补偿前进符号。
- 用户不需要横移功能；控制接口拒绝非零横移速度。底盘转向、行进与六关节在同一耦合任务内协调。
- 几何、风险、策略、模式监督、规划、公共验证、执行和巡检调度各自负责；应用逻辑不加入原 REMANI FSM。
- 计算耗时使用单调墙钟，执行使用 ROS 时间。未知/过期/版本不匹配输入不能作为安全；候选、验证、实际开始、实际完成分别记录。
- 本项目当前做采样验证，不宣称连续安全。源几何检查、完整网格验证、四轮硬限制和实测执行反馈各有职责。

## 如何判定完成

| 范围 | 需要的证据 |
| --- | --- |
| 构建与复现 | C++ 相关包构建通过；源码/安装/运行输入一致；记录模型与地图版本、参数、复现命令和失败报告 |
| 完整任务 | 实际经过配置的所有巡检点并返回捕获的实测起点；不能只看规划路径或首段开始运动 |
| 连续执行 | 正常任务无规划等待停车，后续段在运动中生成；实测每点通过速度、交接连续性与执行器队列状态 |
| 约束与跟踪 | 无横移命令，完整几何和四轮/关节硬约束通过；记录每点位置/臂误差、返航误差和最大跟踪误差 |
| 主动车臂协同 | 具有变姿避障需求的场景中，六关节与底盘同步行动；报告关节运动、避障间隙、通行结果及固定臂同条件对照，证明协同通行收益 |
| 响应速度 | 分开统计搜索、优化、源检查、时间映射、公共验证与端到端响应；报告样本数、失败数、p50/p95/max 和基线条件 |
| 操作与交付 | 真实点击 GUI 完成同版本任务；速度编辑、STOP 和失效停车正常；无死代码或重复配置，知识库与进度更新 |

当前方案建议至少连续三轮闭环、每点位置误差≤0.08 m、臂误差≤0.04 rad、通过速度>0.02 m/s、返航误差<0.04 m。用户更新后首轮完整响应以 1 秒内为工程目标，几百毫秒可接受；原先 p95≤500 ms / 热启动≤200 ms 不再作为本轮阻塞条件。任何指标均需成功任务实测证据，数值调整记录依据。

## 读取与交接

每次开始/恢复任务，按 [目录入口的必读顺序](README.md) 读取开发约定 → 本文件 → 当前进度快照及最新记录 → 知识库/模型/配置 → 协作规则，再查看相关实现和报告。每次构建、验证或启动前重新核对当前快照及相关配置；交接或上下文重建后重新读取，不依赖先前记忆。

每次交接必须指出：当前可用版本、服务状态、已验证效果、未验证改动、失败证据和下一步。先前成功报告只能证明该版本和该输入；不把历史完成当作当前任务完成。
