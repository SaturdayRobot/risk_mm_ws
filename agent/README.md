# Agent 文档管理与读取入口

本目录统一管理 agent 的任务上下文。根 [AGENTS.md](../AGENTS.md) 保留为仓库发现入口，并规定每次任务/运行前读取本目录；目标、知识和进度的正文不在根目录或 docs 中另留副本。

```text
agent/
  README.md                   目录说明与必读顺序
  agent.md                    最终目标、优先级与完成标准
  current_work_progress.md    唯一动态进度、当前方案、变更与实际效果
  collaboration.md            多 agent 分工、共享资源与交接规则
  knowledge/
    README.md                 知识索引、模块职责与运行接口
    robot_model.md            当前模型、坐标、相机、姿态与世界
    configuration.md          配置来源、加载顺序、限值及安装差异
```

## 每次开始或恢复任务

1. 读取根 [AGENTS.md](../AGENTS.md) 与本页。
2. 读取 [最终目标](agent.md)，核对当前用户指令与任务范围。
3. 读取 [进度与当前方案](current_work_progress.md) 的顶部快照、最新逻辑改动和当前技术方案；先确认服务状态、构建情况、未验证修改及下一步。
4. 读取 [知识索引](knowledge/README.md)、[模型](knowledge/robot_model.md) 和 [配置](knowledge/configuration.md)，再查看相关源码与原始报告。
5. 读取 [协作规则](collaboration.md)，单 agent 同样遵守共享资源和证据规则；分派子任务时把这套读取要求交给接手 agent。

每次开始新任务、恢复中断、交接给新 agent 或上下文重建后都执行上述步骤，不能以先前读过或聊天摘要代替。阅读后简要说明本次目标、当前阻塞和下一动作即可，无需复制整份文档。

## 每次构建、验证或启动程序前

重新读取进度顶部当前快照，并核对本次相关的模型/配置/方案；文档有变更时读新内容，长历史按需查。确认源码、install 与启动快照是否一致，判断用户是否仍要求保持服务停止。获准实施时在已有授权范围内连续工作，不为每次常规操作重复询问。

这是 agent 的执行前读取规则，不给机器人或 ROS 控制循环增加 Markdown 解析依赖。仅阅读资料或整理目录的任务不构建算法、不启动服务；是否开展实施和仿真以最新用户指令及当前快照为准。

## 修改与维护

每个逻辑改动开始时追加目的、方案和验收方式。每完成一个可独立验收的节点，按[节点记录规则](current_work_progress.md#节点记录规则)在文末追加带北京时间秒级时间戳的结果，再同步顶部快照。模型或配置变化同步 knowledge。工程设计、碰撞细节和算法来源保留在 `docs/`，通过知识索引引用。原始验收输出保留在 `reports/`，历史报告中的旧路径按生成时的记录解释。
