# Agent 协作与交接

本文件规定需要多 agent 时如何分工；本次文档任务不启动子 agent、服务或仿真。是否使用多 agent 遵守当次用户指令和运行环境权限，小任务由一个 agent 完成即可。

## 共同目标与角色

所有参与者按 [本目录入口](README.md) 的顺序读取目标、当前进度、模型/配置和协作规则；主 agent 的摘要不能替代接手 agent 读取当前文件。恢复或上下文重建后重新读取，构建/验证/启动前核对最新快照。共同目标是当前机器人自主连续巡检与真实可复现效果，不是各自增加模块数量。

| 角色 | 主要责任 | 可交付内容 |
| --- | --- | --- |
| 主 agent / 集成人 | 确定当前任务范围与验收，分配文件、整合实现，统一构建/安装、运行仿真和汇报 | 一个可复现版本、更新后的进度与最终证据 |
| 规划 agent（按需） | 固定输入分析搜索、MINCO、代价与优化；只修改指定规划文件 | 精简修复、离线轨迹/梯度/计时对照、剩余限制 |
| 模型/执行 agent（按需） | 分析坐标、四轮/网格约束、时间映射或执行连续性 | 带坐标和单位的模型证据、指定文件改动、边界回归 |
| 验证/审阅 agent（按需） | 独立复核候选、测试与性能结论，优先只读 | 可复现缺陷、必要测试、证据审阅；不擅自放宽验收条件 |

角色不是长期组织结构；只为当前可独立并行的工作分工。无需同时创建所有角色，不把应用逻辑复制到不同 agent 各自的一套实现中。

## 分工与文件归属

主 agent 派发前用一条简短任务说明：

```text
任务/负责人：
固定输入与目标：
允许修改的文件：
共享接口/禁止变更：
所需验证与报告目录：
交付条件及依赖：
```

先检查工作树已有修改，说明哪些是用户或其他 agent 的工作。共享工作树中，同一文件同时只交给一个写入者；接口变更先同步消费者，公共头文件与 YAML 不允许边构建边修改。确需隔离分支/工作树时记录路径和基线，不能因此 source 另一工作空间或链接旧 install。

完成报告只说明实际编辑的文件与测试，不能以“已有别人的代码”作为覆盖用户工作、git reset、强制 checkout 或清理未提交文件的理由。提交、合并和发布遵守用户授权，不自动把整棵脏工作树打成提交。

## 共享资源必须串行

- **构建/安装：** 同一 build/install 由集成人操作；其他 agent 先交付源码或只读分析。头文件/接口冻结后再构建全部受影响消费者，记录完成结果。
- **Gazebo/GUI/执行器：** 默认由集成人独占；其他 agent 不发布运动命令、不点击控制、不调用 STOP、不重启会话。需要独立仿真时先分配唯一 domain/master 与报告目录，并核对端口/进程，不复用他人会话。
- **文档：** 模型或配置维护者交付事实变更；集成人统一写 `agent/current_work_progress.md` 和知识库公共索引，避免多人追加冲突。
- **报告：** 各任务使用 `reports/<任务或会话>/<尝试编号>`，不要覆盖其他人的 latest/summary；汇总由集成人完成。失败报告保留。
- **进程清理：** 只停止有记录且身份匹配的己方进程。遵守用户最新“停止所有服务”状态；文档读取、审阅与交接不重启服务。

独立只读搜索、审阅及不争用资源的离线工作可并行；有依赖的修改、构建、部署和运动测试按顺序完成。

## 证据和分歧处理

结论注明“源码事实 / 实测结果 / 待验证假设”。性能比较固定模型、地图、起终状态、编译方式、硬件与输入快照；不能用失败候选耗时替代成功任务响应。疑似 jerk、坐标或碰撞问题先保留最小复现，不同时改方向、限位、余量和目标位置后再猜哪一项有效。

出现分歧时给出同一输入的对照与报告，由集成人决定并记录。源算法、四轮适配、公共验证与实际控制的职责不能相互替代；不得为了让各子任务“通过”而降低共同任务标准。发现共享模型/地图/接口变化立即同步，过期结果标记适用版本。

## 交付与集成

每个 agent 的交付应包含以下信息，无需长篇工作流水：

```text
结果：已实现 / 已构建 / 离线通过 / 仿真通过 / GUI通过 / 未完成
改动：文件与原因，是否改变接口、坐标、配置或算法边界
验证：命令、固定输入、报告路径、实际效果（含失败/未运行）
限制：已知问题与尚未验证部分
接续：下一步、服务/进程归属、是否仍有未结束任务
```

集成人检查所有交付和失败结果，处理冲突后进行一次与改动范围匹配的统一验证；核对源码/安装/运行版本，更新知识库及当前进度。所有子任务完成不等于整体目标完成，巡检必须由同一集成版本实际完成全路线。

换 agent 或结束会话前，顶部当前快照至少包含：服务状态、当前构建情况、最近已验证版本与效果、未验证源码、主要阻塞、当前方案和下一条可执行动作。不得只留下“继续优化”而没有输入与证据。
