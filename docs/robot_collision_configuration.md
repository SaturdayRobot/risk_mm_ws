# 机器人碰撞参数与配置

本文件对应当前 Rangermini＋xArm6。长度单位 m，角度 rad，质量 kg；局部碰撞体的中心与尺寸均在所属 link 坐标系表达。机器人 27 个 link、14 个活动关节，URDF 惯性质量合计 85.476098 kg。质量与惯性来自原模型，本轮未重新辨识。

## REMANI 采样碰撞

机械臂碰撞球半径为 **0.030**；每个连杆局部 STL 包围盒划分成由该球覆盖的小单元，球心位于单元中心。六组点数依次为 **60、330、175、84、60、129**，最后一组包含固定末端附件。车体按 STL 表面顶点落入 **0.040** 网格的体素中心采样，球半径 **0.040**，当前共 **1606** 点；这不是整块车体实体的体积填充证明。车体隐藏附件仍参与规划碰撞。

以上采样参数当前由 `load_model` 导出；`remani.yaml` 的 `mm.manipulator_thickness` 已统一为 0.030，删除旧配置 0.044 与实际被覆盖值不一致的问题，没有改变原来的有效 0.030 半径。

| 参数 | 配置值 | C++ 检查中的用途 |
|---|---:|---|
| `grid_map.resolution` | 0.100 | ESDF 栅格分辨率 |
| `grid_map.obstacles_inflation` | 0.050 | 以 `ceil(0.05/0.10)=1` 个体素离散膨胀，不能解释为精确 5 cm 连续外扩 |
| `mm.mobile_base_check_radius` | 0.040 | 车体采样球半径 |
| `mm.manipulator_thickness` | 0.030 | 臂采样球半径 |
| `optimization.safe_margin` | 0.130 | 车体障碍软代价余量；`safe=true` 时也作为环境额外余量 |
| `optimization.safe_margin_mani` | 0.020 | `safe=true` 时臂环境额外余量 |
| `optimization.self_safe_margin` | 0.010 | `safe=true` 时自碰撞额外余量 |
| `optimization.ground_safe_dis` | 0.030 | 臂采样点最低高度检查 |
| `optimization.ground_safe_margin` | 0.020 | 轨迹优化中的地面软惩罚余量 |

`MMConfig` 当前距离阈值：车体对 ESDF 为 `r_base + resolution + (safe ? 0.13 : 0)`；臂对 ESDF 为 `r_arm + (safe ? 0.02 : 0)`；车体对臂为 `r_base + r_arm + (safe ? 0.01 : 0)`；臂对臂为 `2*r_arm + (safe ? 0.01 : 0)`。底盘优化障碍代价在 `r_base+safe_margin=0.17 m` 激活，源几何 `safe=false` 门限仍为 0.14 m；此前 0.03 的旧软余量已提高，修改后巡检转弯仍未验收通过。完整配置与覆盖关系见 [配置知识库](../agent/knowledge/configuration.md)。这些代码路径与优化器代价不是同一个安全保证。

原始车臂碰撞循环从臂组 1 开始，不检查组 0 对车体；近端两组对安装组件有显式豁免。臂自碰撞 owner 对在 `load_model` 中显式定义，与 MoveIt 的 link 级 SRDF 分别维护，不能把一套的通过结果替代另一套。耦合候选另经下述公共全轨迹采样验证，不能用优化器软约束代替公共检查。

## MoveIt 碰撞

MoveIt 读取原始 URDF 的 collision 网格，包括车体 `base_link.stl`、隐藏附件 `base_auxiliary.stl`、六段机械臂和 `head_link.stl`。第六段 collision 使用 `xarm_description/meshes/end_tool/collision/end_tool.stl`；visual 使用 `link6.stl`，两者用途不同。

SRDF 中 34 组豁免均可逐项检查。`FixedAttachment` 对应第六连杆与刚性末端附件，以及通过空安装连杆刚性相接的 `base_link` / `xarm6_link_base`，不对整条臂关闭自碰撞。`stow` 姿态与阻挡场景拒绝的静态服务检查已有报告；此次新增的 `display_arm` 通过 C++ 球模型检查，不据此宣称 MoveIt 完整路径或任意起态均安全。

## 坐标约定、关节与相机

保留当前 URDF、里程计、碰撞网格和四轮运动学使用的模型 `base_link`，不再用它的 +X 表示用户观察到的车头。用户已实测确认 Forward 正确：正前方为 `base_control +X`，该坐标系相对 `base_link` 绕 Z 转 pi；标定唯一来源为 `manual_control.yaml:control_frame_yaw_in_base_rad`，GUI 发布对应静态 TF。手动输入和“前方”目标使用此坐标系，底层驱动仍接收转换后的模型坐标速度。左转绕共同 +Z，横移入口关闭。先前“base_link +X 即雷达侧”的文字判断已被用户实测纠正。

规划模型在 C++ 内将底盘采样点及臂安装矩阵转换到相同的控制基准；世界中的全部碰撞点、机械臂安装和关节几何保持不变。公开任务 yaw 和最终网格验证仍按模型 base_link；规划多项式在适配层转换回该基准。原始模型与碰撞参数不通过翻转相机或修改出生 yaw 补偿。

现有关节后缀 `fl/fr/rl/rr` 是保留的 CAD 标识，不由字面推断物理前后左右；轮位以 URDF 为准。C++ 控制器从 URDF 的转向安装位姿、轮安装位姿和 YAML 轮胎偏移计算接触轮位，不能直接把不同坐标系的 XYZ 相加。驱动轮轴 `[0,-1,0]` 下正轮速对应模型 +X，前进命令经控制基准转换后对应负轮速。

## 关节与相机

四转向关节硬限位 ±1.5708，URDF 速度上限 2 rad/s、effort 30；四驱动关节连续，URDF 速度上限 10 rad/s、effort 20。六个臂关节硬限位依次为 `[-2pi,2pi]`、`[-2.059,2.0944]`、`[-3.927,0.19198]`、`[-2pi,2pi]`、`[-1.69297,pi]`、`[-2pi,2pi]`；URDF 速度为 3.14 rad/s，effort 依次 163.2、163.2、81.6、81.6、30.6、30.6。

MoveIt 规划另限制六关节速度 0.35 rad/s、加速度 0.7 rad/s²。手动仿真上限为臂 0.8 rad/s、转向 1.2 rad/s、轮加速度 4 rad/s²、车体速度 0.8 m/s、偏航 1.0 rad/s、轮速 8 rad/s；指令超时 0.3 s、关节反馈超时 0.5 s。手动接口是底层测试入口，不是已验证轨迹执行入口。

用户确认的带方形面板与圆形镜头的一面是正面。相机光心在 `head_link` 下为 `[-0.005980921,0.068711959,0.012817872]`，朝外轴约 `[0.31270015,0.94820117,0.05597460]`；camera link 的 +X 等于 optical frame 的 +Z。保留与该正面一致的固定安装参数，修正默认关节姿态及 RViz 视角。用户随后确认整个外壳绕法兰翻转 180°：`head_mount` 现在为 XYZ `[-0.0117,-0.0072,0.057]`、RPY `[0,0,pi]`，这是绕法兰左乘旋转，安装偏移同步旋转。相机光心在外壳内的标定保留，传感器与外壳一起翻转。本轮另按用户要求将默认展示构型改为 `[0,-0.56,-1.02,-0.13249348115,-1.50566988238,-1.25102699388]`：相机在模型 base 中约 `[-0.369203,-0.040483,1.366893]`，前向为 `[-1,0,0]`、上向为 `[0,0,1]`。实际 Gazebo 重力下水平误差约 0.53°，五色标靶方向通过。更低但过度伸出车体或发生球模型自碰撞的候选不用于默认姿态，失败检查保留。腕部相机朝向由机械臂姿态决定，车体正前方始终按用户确认使用 +base_control X。

## 耦合候选的公共验证与执行限制

C++ `risk_mm_runtime` 从当前世界 SDF 读取 79 个实体盒与支撑平面；元数据 SHA256 必须一致。边界内自由空间来自该完整静态世界，在线 `/gazebo/model_states` 必须持续包含已知模型且姿态一致。新增、缺失、移动物体或超过 0.5 s 的场景输入均使版本失效并停车；不将缺失输入当作自由空间。

`SampledValidator` 在原始 REMANI 精确多项式上每不超过 0.020 s 采样，并加入全部阶段边界。检查模型/地图版本、九维起终点、p/v/a、阶段连续性、无横向速度、URDF 限位、四轮逆运动学与完整 URDF 网格环境/自碰撞。机器人网格外部 padding 为 0.010 m，SRDF 忽略对保持显式。地面仅豁免四轮接触；其他连杆使用完整网格对支撑平面检查，避免旋转圆轮的局部 AABB 产生虚假下穿。此验证是采样检查，不宣称连续安全。

执行和公共检查的参数集中在 `config/coupled_execution.yaml`：臂速 0.8 rad/s、臂加速度 1.6 rad/s²；车速 1.0 m/s、偏航速度 1.2 rad/s；轮速硬限 10 rad/s（当前 URDF 硬限）、轮加速度 5 rad/s²、转向速度 pi/2 rad/s。原始优化器中的 3.5 rad/s 是软代价参数，仍保留，不以软代价满足替代四轮公开验证。手动模式使用单独较低限速。

执行器独占同一 C++ 驱动适配器，先停止并对齐转向，再按 ROS 时间评价多项式。在线检查实测碰撞、倾斜、姿态与误差；最大允许底盘跟踪误差 0.10 m、偏航 0.35 rad、臂误差 0.08 rad。完成必须实测到位（底盘 0.04 m、偏航 0.05 rad、臂 0.03 rad）且连续三次采样停车。无横移命令，无隐式算法回退；STOP 使待执行计划失效。

整车出生朝向单独由 `gazebo.launch.py` 的 `yaw` 参数控制，默认 pi。它不改变车体正前方定义、不修改相机安装、不修改 `display_arm` 来补偿世界朝向。


原始 REMANI 的末端切向速度为 0.02 m/s，用于保持目标 yaw 的非奇异表达。执行器在多项式终点进入显式制动/收敛阶段，不能把“到达多项式尾点”视为已经停车；公共验证额外对按轮加速度上限得到的直线制动扩展采样三点（当前理想制动时间 0.04 s、距离 0.0004 m），完成还必须依靠实测到位和停车反馈。这些离散检查不构成制动过程的连续安全证明。


`coupled_time_scaling.enabled=true, profile=local` 明确启用局部时间适配；dt/du 的最大局部倍数为 8，最小 0.5，端点至少 1。它保留精确几何，按链式法则重新计算速度与加速度，只在四轮/关节约束允许时加快。报告分别保存平均时间比、最大局部倍数和全部时间映射节点，之后再做完整公共验证；uniform 可显式选作对照，失败不隐式切换。2 ms 导数/轮速检查与最终 20 ms 网格采样不代表连续安全。


当前四轮模型在优化中额外使用 `optimization.four_wheel_min_turning_radius=0.30 m`（代码默认 0 关闭）；与搜索最小转弯半径一致，大于接触轮位最大横向偏移约 0.251 m，避免滚动中要求转向关节从 +90° 跳到 -90°。它是明确列出的物理模型扩展，沿用 base feasibility 权重 100；软代价仍不能代替最终硬约束验证。关闭此参数才是没有该额外目标项的数值原版对照。


GUI 速度默认 0.4 m/s、0.6 rad/s、0.5 rad/s；输入的最大值受手动和公共配置中较小的上限约束。请求还会在后端核验并冻结，编辑后必须重新规划。关节公共速度/加速度由先前保守值 0.35/0.7 明确调整为 0.8/1.6；URDF 的 3.14 rad/s 上限未改变，MoveIt 独立缩回配置仍为 0.35/0.7。轮速 10、轮加速度 5、转向速率 pi/2 与网格 padding 0.01 保留。
